# 当RL学会看地图：从SA到DSA，一个电工杯B题的非典型解法

## 前言

电工杯B题的核心是养老服务站的选址优化——在10个小区里决定在哪建站、建多大，让尽量多的老人被覆盖，同时满意度尽量高。

这道题的标准解法是**完全枚举法**。10个小区、每种有4种选择，总共4^10 = 1,048,576种方案，直接遍历，三秒钟跑完，得到全局最优解。我在提交的论文里就是这么做的。稳定、可靠、不翻车。

但交卷之后，有一个问题一直挥之不去：**枚举法只是“找到”了最优解，它并不“理解”这个解为什么好。** 有没有一种方法，能让模型自己学会选址——不是靠暴力穷举，而是靠对空间结构的感知？

于是就有了这条从SA到DSA的“歧路”。

## 一、SA——先摸清地形

任何探索都需要一个可靠的基线。

我首先用**模拟退火**跑了一次。SA的原理很朴素：在解空间里随机游走，遇到更好的解就接受，遇到更差的解也以一定概率接受，这个概率随“温度”降低而减小。它在0.01秒内找到了一个不错的解——覆盖率79.7%，满意度0.8552，得分0.8009。

SA有两个特性让我印象深刻：它在“探索”和“利用”之间做了很好的平衡。温度高时多探索，温度低时多利用。这就是基线，但我没有停在这里。

## 二、从SA到RL——一个关键的联想

在理解SA的“探索-利用”平衡时，我突然意识到一个问题：**这不是和强化学习的策略梯度在做同一件事吗？** 强化学习的核心思想是：智能体在环境中采取行动，根据奖励信号学习策略。策略梯度方法本质上也是在“探索”和“利用”之间平衡。

于是我开始尝试RL方法。首选是PPO，但它需要同时维护Actor和Critic两个网络，我笔记本跑起来太卡。查阅文献后发现**GRPO**可以用组内相对比较替代Critic，计算量更小、更适合我的场景。

我换上了GRPO，策略网络用最简单的MLP。但结果却不理想——“感觉没学到啥”。MLP只能把输入特征压缩变换，映射到动作概率。但选址问题的核心是**空间关系**——哪个小区离哪个小区近、哪些小区应该被同一个服务站覆盖。MLP这个“眼睛”，根本看不见这些。

| 方法      | 覆盖率 | 满意度 | 得分   |
| --------- | ------ | ------ | ------ |
| SA        | 79.7%  | 0.8552 | 0.8009 |
| GRPO(MLP) | 53.7%  | 0.9362 | 0.7367 |

MLP的方案是6个全小型站，满意度极高但覆盖率惨淡，典型的“偏科”策略。它只学会了“把离得近的人服务好”，完全放弃了对边缘小区的覆盖。

## 三、点亮“眼睛”——Transformer登场

关键转折点来了。

我意识到，问题不在GRPO这个“大脑”，而在于MLP这个“眼睛”。选址问题本质上是**空间布局优化**，策略网络必须能感知小区之间的空间关系。于是我换上了**Transformer的自注意力机制**。

自注意力让每个小区在做决策时，都能“看到”其他所有小区的特征，并根据相似性分配注意力权重。模型不再需要从零猜空间关系，而是可以直接通过注意力计算，发现“小区A和小区B离得近，应该被同一个服务站覆盖”。

效果立竿见影。GRPO+Transformer在加法目标下，得分首次超越了SA。

| 方法                        | 覆盖率          | 满意度           | 得分             |
| --------------------------- | --------------- | ---------------- | ---------------- |
| SA                          | 79.7%           | 0.8552           | 0.8009           |
| GRPO(MLP)                   | 53.7%           | 0.9362           | 0.7367           |
| **GRPO(Transformer)** | **93.1%** | **0.8742** | **0.8203** |

装上了眼睛的GRPO，终于开始“看见”地图了。

## 四、大脑升级与擦亮眼睛

有了能看见全局的眼睛后，我开始优化两个部分。

**大脑升级——IterableGRPO**：普通GRPO的参考策略是训练开始时冻结的，模型学了几百轮，参考策略还停在最初的水平。这就像用几个月前的老地图做导航，自然会出问题。IterableGRPO定期把当前最优策略同步给参考模型，让KL散度惩罚始终基于最新的参考策略计算。结果训练从500轮以上骤降到50轮左右，而且更稳定。

**擦亮眼睛——DSA**：Transformer虽然能“看到”所有小区，但它是全连接的——每个小区都对所有其他小区做注意力，包括那些距离超过1000米、永远不可能互动的冗余连接。这些冗余连接不仅浪费计算，还会稀释关键信号。

| 注意力机制    | 覆盖率           | 满意度           | 目标值           |
| ------------- | ---------------- | ---------------- | ---------------- |
| MLP           | 53.72%           | 0.9362           | 0.503            |
| Transformer   | 89.28%           | 0.9031           | 0.8063           |
| **DSA** | **90.45%** | **0.8923** | **0.8071** |

从MLP到Transformer，目标值提升了60.3%；从Transformer到DSA，覆盖率继续提升1.2个百分点。而且DSA好像找到了这几个小区围成的形状

## 五、与完全枚举法的对比

枚举法是这道题的全局最优基准。我用它和DSA方案做了系统对比 （附效果图）。

| 维度       | 枚举法              | DSA     | 分析                  |
| ---------- | ------------------- | ------- | --------------------- |
| 覆盖率     | 93.13%              | 90.45%  | 枚举法领先2.7个百分点 |
| 满意度     | 0.8777              | 0.8923  | DSA领先1.5个百分点    |
| 目标值     | 0.8171              | 0.8071  | 枚举法略高1.2%        |
| 利用率均衡 | 79%-**99.9%** | 81%-99% | **DSA更均衡**   |
| 单站过载   | I站99.87%           | 无      | **DSA更稳健**   |
| 成本       | 140万               | 119万   | DSA节省21万           |

| 方案   | 站点    | 年度利润         | 总利润 |
| ------ | ------- | ---------------- | ------ |
| 枚举法 | A,B,I,J | 146,15,173,93万  | 428万  |
| DSA    | B,C,E,F | 110,103,35,150万 | 397万  |

![相关的图像，左图枚举，右图优化](https://i0.hdslb.com/bfs/openplatform/8e3f48e9aace0c61f3bd1d8a332f7213c39c8890.png)

结论很清楚：枚举法在绝对分数上依然是最优的——这是暴力搜索的必然结果。但DSA在利用率均衡性、运营稳健性和成本控制上展现了独特的优势。特别是枚举法的I站利用率高达99.87%，几乎没有弹性空间，而DSA的布局没有任何单站过载的问题。DSA方案的利润分布也更均衡，没有那种极低利润的站点。

## 六、完整方法论进化树

```
SA → PPO → GRPO(MLP) → GRPO(Transformer) → IterableGRPO(Transformer) → IterableGRPO(Transformer + DSA)
 ↑      ↑         ↑              ↑                    ↑                          ↑
 基线   试错      轻量化         装上眼睛             学会迭代                   擦亮眼睛
```

每一步都由明确的问题驱动：SA建立了可靠的基线。从SA的“探索-利用”联想到RL，尝试PPO，太卡，换GRPO。GRPO+MLP学不好，意识到“没眼睛”，换Transformer。参考策略滞后，换IterableGRPO实时同步。全连接注意力冗余，换DSA动态聚焦。

## 七、核心洞察：为什么DSA能突破？

标准Transformer的全连接自注意力，在选址问题中存在严重的“注意力冗余”——绝大多数pairwise连接对应的是距离超过服务半径、不可能产生服务关系的小区对。DSA通过动态稀疏化注意力，自动过滤了这些冗余连接。它的注意力矩阵，和选址问题的可达性矩阵在结构上高度一致——模型自己“发现”了哪些小区应该被一起覆盖。

正如那篇改变了整个AI领域的论文标题所言：**Attention Is All You Need.** 在设施选址这个具体问题上，我用自己的实验再次验证了这句话——给模型装上足够好的“注意力之眼”，它就能自己学会看地图。

## 后记

这篇博客记录的不是一个完美的答案，而是一段真实的探索过程。从SA到DSA，从“解题”到“理解”，从“别人说用什么方法”到“我自己追问为什么”。我不知道这是不是一条正路，但它让我真切地感受到了注意力机制的魔力。发出来，是想听听大家的看法。欢迎讨论，欢迎指正。
